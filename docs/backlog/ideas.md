# 다음에 할 것

## 에딧모드 오토 툴 키 (완료, v0.4-p55)

> F가 어플라이 + 컨티뉴가 아니라 어플라이 + 클로즈여야 함. A는 취소, F는 적용.
> 오토툴에서 페인트로 진입한 상태에서는 D 한 번 더 = 전체 채우기 / 빼기 토글, S = 필 모드로. S / D로 왔다갔다.
> D(오토툴 페인트)에서 작업한 사항은 왔다갔다 하는 동안 유지(실수 리스크 감소). A → F 사이에 기능키들이 있는 느낌.
> 어플라이 + 컨티뉴는 G나 다른 키로.

- (메모) 지금: F = Apply & Continue, D = Paint ↔ Fill, Shift+A = 전체 선택 / 해제, Fill → Paint로 가면 새로 전체 선택됨.
  바꿀 것: **F = Apply & Close**, **G = Apply & Continue**, 오토 툴에서 **S = Fill / D = Paint**(Paint에서 D 다시 = 전체 선택 / 해제),
  Fill ↔ Paint를 오가도 Paint에서 고른 부분 유지. 확인할 것: S는 캔버스 위에서 "다음 Object" 키(`v0.4-p19`)와 겹침 → 오토 툴이 켜져 있을 때만 S = Fill.
- (완료) A 취소 · S Fill · D Paint(다시: 전체 선택 / 해제) · F Apply & Close · G Apply & Continue, Paint 선택 유지.

## 창 포커스 없이 프레임 이동 (하지 않음, 2026-09-30)

> 윈도우 포커스 안 된 상태에서도 마우스오버 됐을 때 프레임 이동은 되면 좋겠음.

- (메모) 지금 W A S D / 화살표 hover 이동은 창이 활성일 때만(`isActiveWindow`). 키 입력은 운영체제가 포커스 창으로만 보내므로,
  포커스 없이 되는 것은 **마우스 휠** 정도(Windows는 마우스 아래 창으로 휠을 보냄).
- 결정: 키로는 불가능해서 포기(사용자 판단).

## Pinhole 변환 옵션 리서치 (완료, v0.4-p57 — [`specs/08`](../specs/08-erp-to-pinhole.md) §8)

> 핀홀로 변환할 때 좀 더 다양한 익스포트 옵션이 있음 좋겠음. 표준적으로 쓰는 변환 옵션을 리서치해서 진행하거나,
> 성능 차이가 별로 없어서 필요 없다면 근거 자료를 리서치해서 줘.

- (완료) 배치 프리셋: COLMAP overlapping 12(기본) · Cubemap 6 · Horizon 4 · Two rings 16 · Custom. 배치별 품질 비교 자료는 없음(근거와 출처는 specs/08 §8).

# 보류 / 구상

## 단축키 커스텀 매핑 (장기)

- 사용자가 키를 직접 바꾸는 관리 기능. 지금 키는 `QAction`마다 코드에 있음(`src/app/main_window.py`), F1 표는 `dialogs.SHORTCUTS`.

## 마스크 내보내기 프리셋 바 (좀 더 고민 필요)

> 여러 마스크를 내보낼 때 더 직관적이도록 추가할 수 있는 프리셋 바 형태로. 이름 칸은 텍스트 필드로,
> 바가 1개만 있을 땐 쓸 필요 없이 비활성, 2개 이상이면 활성.

## Sky 생성 중 취소

- 모델을 여러 프레임에 돌리는 동안 멈출 버튼이 없음(끝난 프레임은 캐시에 남으므로 멈춰도 손해 없음). 실제 속도(1024 px 약 0.4초 / 프레임)를 보고 필요하면.
