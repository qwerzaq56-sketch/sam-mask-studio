# 편집 도구 · 미리보기 공통 수칙 (제안서)

Edit Layer 패널, 오토 툴, Mask Preview를 고칠 때 지키는 공통 규칙입니다. `v0.4-p68`~`p88`에서 사용자 피드백으로
고친 문제들(마스크가 날아감, Remove가 반대로 동작, 색이 헷갈림, 키가 꼬임)을 일반 규칙으로 정리했습니다.

같은 범주의 문서:

| 문서 | 내용 |
|---|---|
| 이 문서 | 데이터 안전, 색, 모드 표시, Mask Preview 키 · 툴바, 브러쉬, 검증 |
| [`auto-tools-rules.md`](auto-tools-rules.md) | 오토 툴 켜기 · Fill / Paint · 적용 · 나가기 · Apply to Frames, 각 규칙의 이유 |
| [`by-color.md`](by-color.md) | By Color 선택 규칙(A / B)과 현재 동작 BC-1..19 (피드백용) |

상위 원칙은 [`ux-principles.md`](ux-principles.md), 키는 [`keymap.md`](keymap.md).
공유용 페이지: [360 → 3DGS 워크플로우 개선 계획](https://claude.ai/artifact/KR4Z6dSqVn8dcsBHxpKAB7) 8장의 하위 문서(같은 아티팩트 안 `rules.html`, `auto.html`, `bycolor.html`).

## 1. 데이터 안전

**1-1. 보이는 것과 계산하는 것을 분리한다.** 화면 표시 옵션(Hide Masks, Solo, 👁, Mask Preview, 잘라보기)은 데이터에 손대지 않는다.
편집·브러쉬·도구는 화면 레이어가 아니라 세션의 실제 마스크에서 시작한다.
- 출처: `p82`. Hide Masks가 편집 레이어를 캔버스에 안 넘겨서 브러쉬가 빈 마스크에서 시작 → 획만 남고 기존 마스크가 사라짐.

**1-2. 표시 옵션마다 "켜고 칠해도 마스크가 그대로인가" 회귀 테스트를 둔다.** 새 표시 옵션을 넣을 때는 켠 상태에서 획 하나를 긋고
기존 픽셀이 전부 남는지 확인한다. 고치기 전 코드에서 테스트가 실패하는 것까지 확인한다.

**1-3. 자동 도구는 미리보기만 하고, 적용(Enter / F / G) 전에는 쓰지 않는다.** Undo 한 단계로 되돌릴 수 있어야 한다.
자세한 적용 · 나가기 규칙은 [`auto-tools-rules.md`](auto-tools-rules.md) 4장.

## 2. 색

**2-1. 한 색 = 한 뜻, 겹치지 않는다.** 지금 쓰는 색:

| 색 | 뜻 | 어디 |
|---|---|---|
| Object 색 | 마스크 (편집 중이면 진하게) | 캔버스 |
| 파랑 `(40,110,255)` | 오토 툴이 **넣을** 픽셀 | 오토 툴 미리보기 (`p83`) |
| 주황 `(255,120,0)` | 오토 툴이 **뺄** 픽셀 | 오토 툴 미리보기 (`p83`) |
| 옅은 파랑 / 옅은 주황 | By Color Range의 A / B 중 **그대로인** 픽셀 (바뀌는 픽셀은 진한 파랑 / 주황) | By Color Range (`p86`) |
| 짙은 회색 | Paint 모드에서 아직 안 고른 변화 | 오토 툴 Paint |
| 연두 `(80,255,120)` / 빨강 `(255,60,60)` | 손 편집이 넣은 / 뺀 픽셀 | Show Changes (R) |
| 노랑 / 빨강 | Paint 드래그 중 고르기 / 고르기 해제 영역 | 드래그 중에만 |
| 하늘색 `(0,200,255)` | Region Box | 편집 |
| 옅은 흰색 | By Color 판정 영역(Near edge) | By Color |
| 검정 / 흰색 (또는 회색 체커) | 잘라보기에서 잘린 곳 = 그 자리 마스크 색 | Mask Preview |

- 넣음은 파랑·초록 계열, 뺌은 빨강·주황 계열로 읽히게 한다. 다만 같은 계열 안에서도 **다른 기능끼리는 다른 색**(오토 툴 파랑/주황 ≠ Show Changes 연두/빨강).
- 새 색을 넣기 전에 이 표에서 겹치는지 확인하고, 표를 고친다.
- 출처: `p72` 마젠타 잘라보기 = 오토 툴 마젠타와 겹침, `p83` 마젠타/보라는 넣음/뺌으로 안 읽힘, 초록/빨강은 Show Changes와 겹침.

## 3. 모드와 상태

**3-1. 모드는 켜졌는지, 어떻게 나가는지가 보인다.** 예: Pick Color = 주황 버튼 `Stop Picking (Esc)` + 캔버스 배너, 첫 `Esc`는 피커만 끔(`p79`).

**3-2. 특수 모드의 클릭은 다른 기능으로 새지 않는다.** 색 고르기 중 클릭은 SAM 포인트를 만들지 않는다(`p77`). 그 모드가 필요한 설정을 고르면 모드가 저절로 켜진다(Range → Pick Color). 단 그 모드의 클릭이 이미 만든 것을 바꿔 버리면(고른 색 교체) 저절로 켜지지 않는다(`p92`).

**3-4. 사용자가 공들여 만든 상태는 Undo가 된다.** 마스크뿐 아니라 Region, Paint 고름, By Color의 고른 색도 `Ctrl+Z` 한 단계(`p92`: 다시 켠 피커로 고른 색이 날아가고 되돌릴 수 없었음).

**3-3. 버튼·콤보 글자는 폭 안에 들어간다.** 긴 안내는 배너나 툴팁으로(`p80`). 콤보에는 `&`를 하나만 쓴다(`&&`는 그대로 두 글자로 보임, `p81`).

## 4. Mask Preview 키

**4-1. 키 하나 = 축 하나, 각 축은 자기 상태를 기억한다.** (`p84`)

| 키 | 흑백 상태에서 | 잘라보기 상태에서 |
|---|---|---|
| `X` | Final ↔ Object 전환 | 흑백으로 (Final / Object는 저장된 그대로) |
| `C` | 잘라보기로 (안 / 밖은 저장된 그대로) | 안쪽 ↔ 바깥 전환 |
| `V` | Mask Preview 켜기 / 끄기 | 〃 |
| `Z` (누르고 있기) | 잠깐 보기 | 〃 |

- 세 가지 이상을 한 키로 순환시키지 않는다(`p73`). 토글은 두 상태만.
- 스타일 키는 미리보기를 켜지 않는다(`V` / `Z`만 켬, `p71`).
- 상태(`preview_object`, `preview_style`, `cutout_side`, `cutout_fill`)는 설정 파일에 저장한다.
- 툴바 버튼은 키와 같게(`p87`): `Preview: Final / Object` = `X`, `Cut Out: Inside / Outside` = `C`, 지금 보이는 쪽 버튼이 눌린 상태. `Checker`(잘라보기 바탕 체커), `Overlay` 슬라이더(마스크 색·도구 색 진하기 10–200 %, 저장됨, `p88`)도 툴바에.

## 5. 브러쉬

- 가장 작은 브러쉬 = 이미지 1 px. 화면의 원은 실제로 칠해지는 크기로 그린다(`p83`).
- 크기: Ctrl+좌클릭 드래그 좌우(오른쪽 = 크게, 원은 누른 자리), Ctrl+휠. Ctrl+클릭(움직이지 않고 뗌)은 이미지 조각 더하기 / 빼기 그대로. Ctrl+우클릭은 드래그해도 크기 안 바뀜: 손이 움직여도 누른 자리 조각 빼기(`p108`, 사용자 요청 10-07: 하늘 마스킹 때 자주 씀).
- 빼기 수정키는 Alt(브러쉬·Paint·Region). 크기 조절에 Alt를 쓰지 않는다.

## 6. 검증

- 사용자가 "안 된다"고 하면 **실제 앱 경로**(MainWindow + 실제 크롭)로 재현해서 숫자나 캡처로 확인한 뒤 원인을 말한다. 순수 함수 테스트만으로 판단하지 않는다.
- 동작을 바꾸면 기존 테스트를 새 규칙에 맞게 고치고, 바뀐 이유를 테스트 주석에 단계 번호로 남긴다.
- 테스트 도우미는 Qt 메모리를 복사해서 읽는다(QImage가 해제된 뒤 읽으면 가끔 실패, `p81`).

## 7. 제안 (아직 구현 안 함)

오토 툴 제안은 [`auto-tools-rules.md`](auto-tools-rules.md) 8장(AT-n), By Color 제안은 [`by-color.md`](by-color.md) 3장(BC-Pn).

1. **Mask Preview 상태 표시 한 줄**: 툴바의 `Preview: Final / Object`, `Cut Out: Inside / Outside` 버튼을 `흑백 · Final` / `잘라보기 · 바깥`처럼 한 칸으로 합쳐 지금 상태와 `X` / `C`가 무엇을 바꿀지를 같이 보여 줌.
2. **표시 옵션 회귀 테스트 묶음**: Hide / Solo / 👁 / Mask Preview 각 스타일 × 브러쉬 / 오토 툴 Apply 조합을 하나의 매개변수 테스트로(1-2를 빠짐없이).
3. **브러쉬 크기 드래그를 배율로** (사용자 요청 2026-10-07: Ctrl+드래그 크기 조절이 너무 선형이라 미세 조절이 어려움).
   - 지금: `크기 = 시작 크기 + 2 × 좌우 이동`(화면 px). 크기와 상관없이 마우스 1 px = 지름 2 px. 실제로 칠하는 지름은 이미지 px로 `2r + 1`(홀수)이라 100% 배율에서는 마우스 1 px마다 한 단계씩 바뀌고, 작은 브러쉬일수록 원하는 크기에 멈추기 어려움.
   - **a. 배율 곡선(핵심)**: `크기 = 시작 크기 × 2^(좌우 이동 / 150)`. 오른쪽 150 px = 두 배, 왼쪽 150 px = 절반. 5 px 근처는 천천히, 300 px 근처는 빠르게 움직여 어느 크기에서나 같은 비율로 조절됨. 1 ↔ 800 전체가 좌우 약 1450 px 안에 들어감.
   - **b. 크기 숫자 표시**: 드래그하는 동안 원 옆에 칠해지는 지름을 이미지 px로 표시(`9 px`). 같은 숫자에 머무는 구간이 보여 멈출 자리를 고르기 쉬움.
   - **c. 정밀 조절**: 드래그 중 Shift를 누르면 속도 1/4. 누른 순간의 위치와 크기를 새 시작점으로 잡아 크기가 튀지 않음.
   - **d. Ctrl+휠도 같은 기준**: 한 칸 = ×1.1(지금처럼)이되, 이미지 지름이 실제로 한 단계(`2r + 1` → `2r + 3`) 이상 바뀌도록 최소 단계를 이미지 px로 맞춤. 지금은 최소 2 화면 px라 크게 확대한 상태에서는 휠을 여러 번 굴려도 칠하는 크기가 안 바뀜.
   - 추천 순서: a + b 먼저(작은 변경, 체감 큼), c는 a만으로 부족할 때, d는 a와 함께.
