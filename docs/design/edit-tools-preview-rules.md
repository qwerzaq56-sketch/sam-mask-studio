# Edit 패널 · 오토 툴 · Mask Preview 수칙 (제안서)

Edit Layer 패널, 오토 툴(특히 By Color), Mask Preview를 고칠 때 지키는 규칙입니다. `v0.4-p68`~`p84`에서 사용자 피드백으로
고친 문제들(마스크가 날아감, Remove가 반대로 동작, 색이 헷갈림, 키가 꼬임)을 일반 규칙으로 정리했습니다.
상위 원칙은 [`ux-principles.md`](ux-principles.md), 키는 [`keymap.md`](keymap.md). 마지막 절은 아직 구현하지 않은 제안입니다.
공유용 페이지: [편집 도구 · 미리보기 수칙](https://claude.ai/artifact/JEJbPmcFfefHebuFTcMDFF) (360 → 3DGS 워크플로우 개선 계획 8.2의 하위 문서). 9절 By Color 현재 동작은 피드백용입니다.

## 1. 데이터 안전

**1-1. 보이는 것과 계산하는 것을 분리한다.** 화면 표시 옵션(Hide Masks, Solo, 👁, Mask Preview, 잘라보기)은 데이터에 손대지 않는다.
편집·브러쉬·도구는 화면 레이어가 아니라 세션의 실제 마스크에서 시작한다.
- 출처: `p82`. Hide Masks가 편집 레이어를 캔버스에 안 넘겨서 브러쉬가 빈 마스크에서 시작 → 획만 남고 기존 마스크가 사라짐.

**1-2. 표시 옵션마다 "켜고 칠해도 마스크가 그대로인가" 회귀 테스트를 둔다.** 새 표시 옵션을 넣을 때는 켠 상태에서 획 하나를 긋고
기존 픽셀이 전부 남는지 확인한다. 고치기 전 코드에서 테스트가 실패하는 것까지 확인한다.

**1-3. 자동 도구는 미리보기만 하고, 적용(Enter / F / G) 전에는 쓰지 않는다.** Undo 한 단계로 되돌릴 수 있어야 한다.

## 2. 선택 규칙 (By Color Range 기준, 다른 선택형 도구도 같게)

**2-1. A / B로 말한다.** 필터(고른 색과 허용치, 밝기 범위)가 잡은 영역 = **A**, 판정 영역 안의 나머지 = **B**.

| 동작 | A | B |
|---|---|---|
| Add & Remove (기본) | 넣음 | 뺌 |
| Add only | 넣음 | 그대로 |
| Remove only | 그대로 | 뺌 |
| Invert 체크 | A와 B를 바꾼 뒤 위 규칙 | |

- Add와 Remove는 **같은 A / B 기준**이다. "Remove = A를 빼기"처럼 기준이 바뀌는 동작은 만들지 않는다(`p75`~`p80`의 실수, `p81`에서 정리).
- Invert는 **A와 B만** 바꾼다. 작업 위치를 바꾸거나 동작 종류를 바꾸지 않는다.

**2-2. 판정 영역은 눈에 보인다.** Near edge 띠(또는 Region) 안만 판정하면 그 범위를 화면에 깐다(옅은 흰색, `p79`).
영역 안 픽셀은 넣음 / 뺌 / 그대로-안 / 그대로-밖 넷 중 하나로 읽혀야 한다.

**2-3. 색 비교는 밝기를 포함한다.** a\*b\*만 쓰면 흰 하늘과 어두운 회녹색 잎이 같은 색이 된다(`p78`: 하늘색 허용치 20에서 나무의 38–48 %).

**2-4. 의미를 바꾸기 전에 사용자 말로 규칙을 한 줄씩 적고 확인한다.** "Replace", "Keep" 같은 이름은 사람마다 다르게 읽는다.
동작 표(위 2-1처럼)를 먼저 맞추고 구현한다.

## 3. 색

**3-1. 한 색 = 한 뜻, 겹치지 않는다.** 지금 쓰는 색:

| 색 | 뜻 | 어디 |
|---|---|---|
| Object 색 | 마스크 (편집 중이면 진하게) | 캔버스 |
| 파랑 `(40,110,255)` | 오토 툴이 **넣을** 픽셀 | 오토 툴 미리보기 (`p83`) |
| 주황 `(255,120,0)` | 오토 툴이 **뺄** 픽셀 | 오토 툴 미리보기 (`p83`) |
| 옅은 파랑 / 옅은 주황 | By Color Range의 A / B 중 **그대로인** 픽셀 (바뀌는 픽셀은 진한 파랑 / 주황) | By Color Range (`p86`) |
| 짙은 회색 | Paint 모드에서 아직 안 고른 변화 | 오토 툴 Paint |
| 연두 `(80,255,120)` / 빨강 `(255,60,60)` | 손 편집이 넣은 / 뺀 픽셀 | Show Changes (R) |
| 노랑 / 빨강 | Paint 드래그 중 고르기 / 고르기 해제 영역 | 드래그 중에만 |
| 하늘색 `(0,200,255)` | Region Box | 편집 |
| 옅은 흰색 | By Color 판정 영역(Near edge) | By Color |
| 검정 / 흰색 (또는 회색 체커) | 잘라보기에서 잘린 곳 = 그 자리 마스크 색 | Mask Preview |

- 넣음은 파랑·초록 계열, 뺌은 빨강·주황 계열로 읽히게 한다. 다만 같은 계열 안에서도 **다른 기능끼리는 다른 색**(오토 툴 파랑/주황 ≠ Show Changes 연두/빨강).
- 새 색을 넣기 전에 이 표에서 겹치는지 확인하고, 표를 고친다.
- 출처: `p72` 마젠타 잘라보기 = 오토 툴 마젠타와 겹침, `p83` 마젠타/보라는 넣음/뺌으로 안 읽힘, 초록/빨강은 Show Changes와 겹침.

## 4. 모드와 상태

**4-1. 모드는 켜졌는지, 어떻게 나가는지가 보인다.** 예: Pick Color = 주황 버튼 `Stop Picking (Esc)` + 캔버스 배너, 첫 `Esc`는 피커만 끔(`p79`).

**4-2. 특수 모드의 클릭은 다른 기능으로 새지 않는다.** 색 고르기 중 클릭은 SAM 포인트를 만들지 않는다(`p77`). 그 모드가 필요한 설정을 고르면 모드가 저절로 켜진다(Range → Pick Color).

**4-3. 버튼·콤보 글자는 폭 안에 들어간다.** 긴 안내는 배너나 툴팁으로(`p80`). 콤보에는 `&`를 하나만 쓴다(`&&`는 그대로 두 글자로 보임, `p81`).

## 5. Mask Preview 키

**5-1. 키 하나 = 축 하나, 각 축은 자기 상태를 기억한다.** (`p84`)

| 키 | 흑백 상태에서 | 잘라보기 상태에서 |
|---|---|---|
| `X` | Final ↔ Object 전환 | 흑백으로 (Final / Object는 저장된 그대로) |
| `C` | 잘라보기로 (안 / 밖은 저장된 그대로) | 안쪽 ↔ 바깥 전환 |
| `V` | Mask Preview 켜기 / 끄기 | 〃 |
| `Z` (누르고 있기) | 잠깐 보기 | 〃 |

- 세 가지 이상을 한 키로 순환시키지 않는다(`p73`). 토글은 두 상태만.
- 스타일 키는 미리보기를 켜지 않는다(`V` / `Z`만 켬, `p71`).
- 상태(`preview_object`, `preview_style`, `cutout_side`, `cutout_fill`)는 설정 파일에 저장한다.
- 툴바 버튼은 키와 같게(`p87`): `Preview: Final / Object` = `X`, `Cut Out: Inside / Outside` = `C`, 지금 보이는 쪽 버튼이 눌린 상태. `Checker`(잘라보기 바탕 체커), `Overlay` 슬라이더(마스크 색·도구 색 진하기 10–200 %, 저장됨, `p88`)도 툴바에.

## 6. 브러쉬

- 가장 작은 브러쉬 = 이미지 1 px. 화면의 원은 실제로 칠해지는 크기로 그린다(`p83`).
- 크기: Ctrl+드래그 좌우(오른쪽 = 크게, 원은 누른 자리), Ctrl+휠. Ctrl+클릭(움직이지 않고 뗌)은 이미지 조각 더하기 / 빼기 그대로.
- 빼기 수정키는 Alt(브러쉬·Paint·Region). 크기 조절에 Alt를 쓰지 않는다.

## 7. 검증

- 사용자가 "안 된다"고 하면 **실제 앱 경로**(MainWindow + 실제 크롭)로 재현해서 숫자나 캡처로 확인한 뒤 원인을 말한다. 순수 함수 테스트만으로 판단하지 않는다.
- 동작을 바꾸면 기존 테스트를 새 규칙에 맞게 고치고, 바뀐 이유를 테스트 주석에 단계 번호로 남긴다.
- 테스트 도우미는 Qt 메모리를 복사해서 읽는다(QImage가 해제된 뒤 읽으면 가끔 실패, `p81`).

## 8. 제안 (아직 구현 안 함)

1. **색 범례**: 오토 툴이 켜져 있을 때 캔버스 구석에 작은 범례(파랑 = 넣음, 주황 = 뺌, 회색 = 안 고름, 흰 띠 = 판정 영역). 3장의 색 표를 화면에서 바로 읽게.
2. **Mask Preview 상태 표시 한 줄**: 툴바 버튼 두 개(`Preview: Final / Object`, `Style: …`)를 `흑백 · Final` / `잘라보기 · 바깥`처럼 한 칸으로 합쳐 지금 상태와 `X` / `C`가 무엇을 바꿀지를 같이 보여 줌.
3. **선택(A)만 보기**: By Color Range에서 키를 누르고 있는 동안 A만 칠해 보여 줌(넣음/뺌과 별개로 "필터가 무엇을 잡았나" 확인). Photoshop Color Range의 흑백 미리보기와 같은 역할.
4. **Paint 드래그 색 정리**: 드래그 중 노랑은 주황(뺌)과 가까움. 드래그 영역을 흰 점선 윤곽으로 바꾸는 것을 검토.
5. **표시 옵션 회귀 테스트 묶음**: Hide / Solo / 👁 / Mask Preview 각 스타일 × 브러쉬 / 오토 툴 Apply 조합을 하나의 매개변수 테스트로(1-2를 빠짐없이).
6. **허용치 단위 안내**: Color within 옆에 "Lab ΔE, 20–30 = 비슷한 하늘색"처럼 감 잡을 수 있는 안내.

## 9. By Color 현재 동작 (피드백용, `v0.4-p84` 기준)

아래 항목마다 `피드백:` 칸에 **O(맞음) / X(틀림) / 원하는 동작**을 적어 주세요. 번호(BC-n)로 말해 주셔도 됩니다.
코드 위치: 계산 `src/app/session.py` `compute_tool`, 필터 `src/core/refine.py` `select_range` / `near_edge`, 화면 `src/app/properties_panel.py`.

### 9-1. Range 처리 순서

```
① 색 고르기 → ② 필터로 A 만들기 → ③ (Invert면 A↔나머지) → ④ 판정 영역으로 자르기 → ⑤ 동작(넣기/빼기) → ⑥ 미리보기 → ⑦ 적용
```

**BC-1. 색 고르기.** Range를 고르면 Pick Color가 저절로 켜진다. 클릭 = 그 자리 **5×5 px 평균색** 하나로 **교체**,
Shift+클릭 = 하나 **추가**(최대 8개, 넘으면 오래된 것부터 버림). `Clear` = 전부 지움. 색은 화면 이미지(작업 해상도, BC-9)에서 읽는다.
- 피드백:

**BC-2. 색 필터 (Color within, 기본 켜짐, 허용치 30).** 고른 색 **중 하나라도**와 Lab 거리(밝기 L 0–100, a\*, b\*)가 허용치 이하면 A.
밝기 차이도 거리에 들어간다(`p78`). 예: 같은 하늘색이라도 밝기가 30 넘게 다르면 A가 아니다.
- 피드백:

**BC-3. 밝기 필터 (Brightness from … to, 기본 꺼짐).** 회색값(0–255)이 범위 안이면 A.
색 필터와 **둘 다 켜면 AND**(둘 다 만족해야 A). 색을 안 골랐고 밝기도 꺼져 있으면 A가 비고 영역 전체가 B가 된다(아래 BC-6 ※).
- 피드백:

**BC-4. Invert.** A와 B를 바꾼다(필터가 잡은 픽셀 = B, 나머지 = A). 판정 영역이나 동작 종류는 그대로.
- 피드백:

**BC-5. 판정 영역 (Near edge, 기본 켜짐 30 px).** **지금 마스크의 경계**에서 안쪽·바깥쪽으로 30 px 이내만 판정한다(화면의 옅은 흰 띠).
띠 밖은 A든 B든 **그대로**. 끄면 이미지 전체. Region 박스가 있으면 그 안으로 한 번 더 자른다. 이미지 테두리는 경계로 치지 않는다.
- 피드백:

**BC-6. 동작 (Changes).** 판정 영역 안에서만:

| Changes | A (잡힌 픽셀) | B (영역 안 나머지) |
|---|---|---|
| Add A & Remove B (기본) | 마스크에 넣음 | 마스크에서 뺌 |
| Add only (A) | 넣음 | 그대로 |
| Remove only (B) | 그대로 | 뺌 |

※ 색을 하나도 안 고른 채 기본 동작(또는 Remove only)이면 영역 안 전부가 B라서 **띠 안의 마스크가 전부 빠진다**(규칙대로지만, Range를 막 고른 순간 미리보기가 띠 전체 주황으로 보임). 색을 고르기 전에는 아무 것도 안 바꾸게 할지 확인 필요.
- 피드백:

**BC-7. 미리보기.** (`p86`) 판정 영역의 **모든 픽셀을 A = 파랑, B = 주황**으로 칠한다. 실제로 바뀌는 픽셀(A인데 마스크 밖 = 넣음, B인데 마스크 안 = 뺌)은 진하게, 그대로인 픽셀은 옅게. 원래 마스크 색은 그 아래로 비쳐 보이고(색을 덮어쓰지 않고 섞음) 경계는 흰 선. 전에는 바뀌는 픽셀만 칠해서, A인데 이미 마스크 안이거나 B인데 이미 밖인 픽셀이 "둘 다 아닌" 것처럼 보였다. 패널에 `Will apply: +N px / −N px`.
설정을 바꾸면 잠깐 뒤 다시 계산한다(작업 해상도 기준, 화면 스레드 밖).
- 피드백:

**BC-8. 적용.** Fill 모드: Enter로 전체 결과 적용(Undo 한 번). Paint 모드: 붓으로 문지른 곳만 적용.
`Apply to All Frames`: 같은 설정·같은 고른 색으로 이 Object의 다른 프레임에도 적용(프레임마다 그 프레임 마스크의 경계로 띠를 다시 잡음).
- 피드백:

### 9-2. Auto: Color / Auto: Brightness (색을 고르지 않는 방식)

**BC-10. Auto: Color.** 띠 안의 색을 8개 무리로 나누고(k-means, Lab), 지금 마스크가 **절반 넘게** 덮은 무리는 마스크 쪽, 아니면 밖으로 다시 칠한다.
Balance가 50보다 크면 마스크 쪽을 더 많이 준다. 마스크가 대충 맞아야 결과가 맞다.
- 피드백:

**BC-11. Auto: Brightness.** 띠 안 회색값에 Otsu 기준선 하나. 마스크 쪽이 더 밝으면 밝은 픽셀이 마스크.
- 피드백:

### 9-3. 기대와 어긋날 수 있는 지점 (확인 필요)

"하늘 마스크 안에 칠해진 나뭇잎 픽셀을 빼기"(`p78` 요청)를 기준으로, 지금 구조에서 안 되는 경우입니다.

**BC-12. 마스크 안쪽 깊숙이 있는 잎은 판정 영역 밖.** 띠는 **마스크 경계** 기준이다. 하늘 마스크가 잎을 덮어 버렸다면 그 자리에는 경계가 없어서,
경계에서 30 px보다 먼 잎은 아무리 색을 골라도 안 바뀐다. 해결 후보: (a) 그 작업에는 Near edge 끄기(+ Remove only), (b) 띠 기준을 "마스크 경계"가 아니라 "마스크 안 전체"로 바꾸는 옵션.
- 피드백:

**BC-13. Near edge를 끄고 기본 동작(Add & Remove)을 쓰면** 이미지 전체에서 고른 하늘색과 비슷한 것(흰 벽, 흰 차, 밝은 도로)이 마스크에 **들어온다**. 잎만 빼려면 Remove only가 맞다. 기본 동작을 바꿀지, 경고를 띄울지.
