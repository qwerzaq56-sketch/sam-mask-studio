# 오토 툴 수칙 (제안서)

Edit Layer의 오토 툴(Object Fill · Fill Holes · Remove Specks · Grow · Shrink · Close Gaps · Invert · By Color)이 켜지고, 미리보이고,
적용되거나 버려지는 규칙입니다. 이미 구현된 동작을 기준(`v0.4-p88`)으로, 각 규칙의 **이유**와 **출처 단계**를 같이 적었습니다.
공통 수칙(데이터 안전, 색, 모드 표시, Mask Preview, 브러쉬)은 [`edit-tools-preview-rules.md`](edit-tools-preview-rules.md),
By Color의 세부 동작과 피드백 항목은 [`by-color.md`](by-color.md), 키 전체는 [`keymap.md`](keymap.md).
공유용 페이지: [360 → 3DGS 워크플로우 개선 계획](https://claude.ai/artifact/KR4Z6dSqVn8dcsBHxpKAB7) 안의 `auto.html`.

코드: `src/app/main_window.py` (`set_brush_tool`, `set_auto_mode`, `close_tool`, `reapply_tool`, `apply_tool_to_all`, `escape`,
`leave_auto_key`, `f_key` / `g_key` / `s_key`), `src/app/session.py` (`auto_*`, `pick*`, `apply_auto`, `close_auto`).

## 1. 한 장 요약

```
도구 버튼 ─▶ Fill 모드(결과 전체 미리보기) ─┬─ Enter / G  : 적용하고 계속 (다시 계산)
                 ▲      │ D               ├─ F / Shift+Enter : 적용하고 닫기
                 │ S    ▼                 └─ A / Esc / 같은 버튼 : 버리고 닫기
              Paint 모드(브러쉬로 일부 고르기)       그 밖의 모든 나가기 = 버림
```

| 키 | 동작 | 버튼 |
|---|---|---|
| `A` | 나가기, 결과 버림 | 같은 도구 버튼 다시 |
| `S` | Fill 모드 (Paint의 고름은 유지) | `Fill` |
| `D` | Paint 모드 · Paint에서 다시 = 전체 고르기 ↔ 없음 | `Paint` |
| `F` · `Shift+Enter` | 적용하고 닫기 | `Apply & Close` |
| `G` · `Enter` | 적용하고 계속 | `Apply & Continue` |
| `Esc` | 색 고르기 끄기 → 도구 나가기(버림) → 편집 끝, 한 번에 한 단계 | – |
| `Shift+A` | Paint: 전체 고르기 ↔ 없음 | – |

**이유**: 왼손 홈 줄 한 줄(`A S D F G`)에 "취소 · 두 모드 · 확정 · 계속"을 순서대로 놓았다. 손을 옮기지 않고 미리보기 → 고르기 → 확정이 끝난다(`p49`, `p55`).

## 2. 켜기

**2-1. 켜면 바로 결과가 보인다.** 버튼을 누르는 순간 지금 설정으로 계산해 미리보기를 깐다. 빠른 도구는 화면 스레드에서, 이미지를 읽는
도구(Object Fill, By Color)는 백그라운드에서(패널에 `Computing…`).
- 이유: 들어가면 바로 쓸 것이 켜져 있다([`ux-principles.md`](ux-principles.md) 2). 설정을 만지기 전에 무엇을 하는 도구인지 결과로 보인다.

**2-2. 항상 Fill 모드로 시작한다.** 이전 도구가 Paint였어도 새 도구는 Fill.
- 이유: 고르기(Paint)는 결과를 본 다음의 일이다. 시작 상태가 매번 같아야 키 순서(보기 → `D` → 고르기)가 손에 붙는다(`p15`).

**2-3. 한 번에 하나.** 다른 오토 툴이나 브러쉬를 켜면 지금 도구는 **결과를 버리고** 닫힌다. 같은 도구 버튼을 다시 누르면 `A`와 같다.

**2-4. Region 안에서만.** Region Box가 있으면 결과는 그 안에서만 쓰이고 바깥은 그대로(미리보기도 그 안만). Region은 Undo가 되고, 편집 대상(Object·프레임)이 바뀌면 사라진다.
- 이유: 자동 결과를 "여기만" 받고 싶은 경우가 대부분이라, 도구마다 범위 설정을 두지 않고 Region 하나로 통일.

## 3. Fill 모드와 Paint 모드

**3-1. 같은 결과를 두 방식으로 받는다.** 결과(계산)는 하나다. Fill = 전부, Paint = 브러쉬로 고른 부분만.

| | Fill | Paint |
|---|---|---|
| 적용되는 것 | 결과 전체 (Region 안) | 고른 부분 |
| 화면 | 파랑 = 넣음, 주황 = 뺌 | 고른 부분 파랑 / 주황, 안 고른 변화 짙은 회색 |
| 패널 | `Will apply: +N px / −N px` | `Will apply: +n / −n (of +N / −N)` |
| 마우스 | 캔버스 클릭은 평소대로(포인트) | 드래그 = 고르기, `Alt`+드래그 = 해제 |
| Apply to All Frames | 있음 | 없음 (고름은 한 이미지 것) |

**3-2. Paint에 처음 들어가면 전부 고른 상태.** Fill에서 보던 것이 그대로 남고, 거기서 **빼 나가는** 식으로 고친다.
- 이유: 같은 결과로 가는 길은 같은 상태에서 시작한다(ux 3). 대부분 "거의 다 맞고 몇 군데만 틀림"이라 빼는 쪽이 빠르다(`p15`).

**3-3. Fill ↔ Paint를 오가도 Paint의 고름은 남는다.** Fill로 전체를 확인하고 Paint로 돌아오면 고르던 것이 그대로.
- 이유: 오가며 확인하는 것이 작업을 날리면 안 된다(`p55`).

**3-4. 고르기도 Undo가 된다.** Paint의 획 하나 = Undo 한 단계(`Ctrl+Z`). 적용한 뒤의 `Ctrl+Z`는 적용 자체를 되돌린다.

## 4. 적용과 나가기

**4-1. 적용은 명시적으로만.** `Enter` / `G` / `F` / `Shift+Enter` / 적용 버튼. **그 밖의 모든 나가기는 결과를 버린다**:
`A`, `Esc`, 같은 버튼, 다른 도구, 편집 끝내기(`E`, `D`), 새 Object(`N`), 전파 시작, 디텍션 고르기.
- 이유: 미리보기는 데이터가 아니다(공통 수칙 1-3). 실수로 나가도 마스크는 그대로이고, 버린 결과는 버튼 한 번이면 다시 계산된다.
  반대로 "나가면 적용"이면 확인하지 않은 결과가 조용히 쓰인다.

**4-2. 적용하고 계속(`Enter` / `G`)** = 적용(Undo 한 단계) → 고름 초기화 → **새 마스크로 다시 계산**해 다음 결과를 보여 줌. 도구는 켜진 채.
- 이유: Grow · Fill Holes처럼 여러 번 거듭 거는 도구, By Color처럼 색을 바꿔 가며 여러 번 받는 작업을 한 흐름으로.

**4-3. 적용하고 닫기(`F` / `Shift+Enter`)** = 적용 후 도구를 끄고 포인트 편집으로 돌아감.

**4-4. `Esc`는 한 번에 한 단계.** 색 고르기 중이면 고르기만 끔 → 도구가 켜져 있으면 도구만 닫음(버림) → 아무 도구도 없으면 편집 끝.
- 이유: 모드는 나가는 법이 보이고, 한 번 누름에 한 층씩 벗겨져야 어디까지 나갔는지 안다(공통 수칙 3-1, `p79`).

**4-5. 프레임을 넘기면**: 결과는 버려지고 새 프레임에서 같은 Object 편집이 이어진다(오토 툴은 꺼짐). 단, **Paint에서 고른 것이 아직
안 쓰였으면 넘어가지 않는다**: 상태 표시줄에 `The auto tool's picks are not written in yet: Enter applies them, Esc drops them`.
- 이유: Paint의 고름은 사람이 시간을 들인 작업이라 조용히 버리지 않는다. Fill 결과는 다시 계산하면 그만이라 막지 않는다.

**4-6. 적용은 한 번 = Undo 한 단계.** 여러 프레임에 한 번에 쓰는 Apply to All Frames도 Undo 한 번.

## 5. Apply to All Frames

- Fill 모드에서만. 지금 설정으로 **이 Object가 마스크를 가진 모든 프레임**에 같은 도구를 건다(Region이 있으면 그 안만).
- 시작 전에 확인 창 하나(프레임이 많아 시간이 걸리고 결과를 한눈에 볼 수 없으므로). 백그라운드에서 돌고, 끝나면 `N of M frame(s)` 로그.
- 그 사이 마스크가 바뀐 프레임, 이미지 크기가 다른 프레임은 **건너뛰고** 개수를 알린다.
- 이유: 자동 결과를 수십 장에 확인 없이 쓰므로, 손댄 프레임은 덮지 않는 쪽이 안전하다. 되돌리기는 Undo 한 번.

## 6. 미리보기 표시

**6-1. 바뀌는 것만 진하게, 색은 넣음 파랑 · 뺌 주황.** Show Changes(연두 / 빨강)와 섞이지 않는 별도 색(`p83`).
By Color Range는 판정하는 모든 픽셀을 A = 파랑 / B = 주황으로 칠하고, 바뀌는 픽셀만 진하게(`p86`, [`by-color.md`](by-color.md)).

**6-2. 원래 마스크가 비쳐 보인다.** 도구 색은 편집 중인 마스크 색을 덮어쓰지 않고 그 위에 섞는다. 경계는 흰 선(`p86`).
진하기는 툴바 `Overlay` 슬라이더로(`p88`).

**6-3. 보이는 색 = 지금 결과.** 설정을 바꿔 다시 계산하는 동안에는 옛 결과와 새 설정을 섞어 그리지 않는다(`p86`).

**6-4. 결과는 저절로 새로 계산된다.** 도구 밖에서 마스크가 바뀌면(Undo, 포인트 클릭, Ctrl+클릭) 결과를 다시 계산한다.
설정 중 **그 도구가 쓰는 값**이 바뀔 때만 다시 계산한다(다른 도구의 슬라이더는 영향 없음).

## 7. 새 오토 툴을 만들 때

1. 결과는 "지금 마스크 → 새 마스크" 하나로 낸다(`compute_tool`). 넣음 / 뺌은 그 차이로 저절로 나온다.
2. 쓰는 설정 이름을 `AUTO_PARAMS`에 적는다(캐시와 다시 계산 기준).
3. 이미지를 읽으면 `IMAGE_TOOLS`에 넣어 백그라운드로.
4. 선택형(무엇을 고르고 넣을지 / 뺄지)이면 A / B 규칙을 따른다([`by-color.md`](by-color.md) 1장).
5. 위 4장의 나가기 규칙, 6장의 색은 그대로 쓴다. 새 색이 필요하면 공통 수칙의 색 표부터 고친다.

## 8. 제안 (아직 구현 안 함)

| # | 제안 | 이유 |
|---|---|---|
| AT-1 | **버릴 때 한 줄 알림**: 적용 안 한 결과를 버리고 나가면 상태 표시줄에 `Dropped: +N / −N px (Ctrl+Z 없음, 다시 켜면 다시 계산)` | 4-1이 안전하지만 "왜 안 들어갔지?"가 생길 수 있음 |
| AT-2 | **색 범례**: 오토 툴이 켜져 있을 때 캔버스 구석에 파랑 = 넣음 · 주황 = 뺌 · 회색 = 안 고름 (Range: A / B) | 색 뜻을 화면에서 바로 |
| AT-3 | **Paint 모드 배너**: `PAINT · drag: pick · Alt: unpick · D: all / none · S: Fill` | Pick Color 배너처럼 모드와 나가는 법이 보이게 |
| AT-4 | **Apply to All 미리보기 몇 장**: 확인 창에 3–4장 썸네일 | 수십 장에 쓰기 전에 결과를 눈으로 |
| AT-5 | **Paint 드래그 색 정리**: 드래그 중 노랑(고르기)이 주황(뺌)과 가까움. 흰 점선 윤곽으로 | 한 색 = 한 뜻(공통 수칙 2-1) |
