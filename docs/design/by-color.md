# By Color: 선택 규칙과 현재 동작 (피드백용)

By Color 오토 툴이 무엇을 A / B로 고르고, 어떻게 넣고 빼는지입니다(`v0.4-p88` 기준). 켜기 · Fill / Paint · 적용 · 나가기처럼
모든 오토 툴에 같은 규칙은 [`auto-tools-rules.md`](auto-tools-rules.md), 색 · 데이터 안전 같은 공통 수칙은
[`edit-tools-preview-rules.md`](edit-tools-preview-rules.md).
공유용 페이지: [360 → 3DGS 워크플로우 개선 계획](https://claude.ai/artifact/KR4Z6dSqVn8dcsBHxpKAB7) 안의 `bycolor.html`.

2장의 항목마다 `피드백:` 칸에 **O(맞음) / X(틀림) / 원하는 동작**을 적어 주세요. 번호(BC-n)로 말해 주셔도 됩니다.
코드 위치: 계산 `src/app/session.py` `compute_tool` / `auto_ab`, 필터 `src/core/refine.py` `select_range` / `near_edge`, 화면 `src/app/properties_panel.py`.

## 1. 선택 규칙 (By Color Range 기준, 다른 선택형 도구도 같게)

**1-1. A / B로 말한다.** 필터(고른 색과 허용치, 밝기 범위)가 잡은 영역 = **A**, 판정 영역 안의 나머지 = **B**.

| 동작 | A | B |
|---|---|---|
| Add & Remove (기본) | 넣음 | 뺌 |
| Add only | 넣음 | 그대로 |
| Remove only | 그대로 | 뺌 |
| Invert 체크 | A와 B를 바꾼 뒤 위 규칙 | |

- Add와 Remove는 **같은 A / B 기준**이다. "Remove = A를 빼기"처럼 기준이 바뀌는 동작은 만들지 않는다(`p75`~`p80`의 실수, `p81`에서 정리).
- Invert는 **A와 B만** 바꾼다. 작업 위치를 바꾸거나 동작 종류를 바꾸지 않는다.

**1-2. 판정 영역 안의 모든 픽셀은 A 아니면 B로 보인다.** 판정 영역(Near edge 띠 또는 Region)은 옅은 흰색으로 깔고(`p79`),
그 안을 A = 파랑, B = 주황으로 칠한다. 바뀌는 픽셀은 진하게, 그대로인 픽셀은 옅게(`p86`). "둘 다 아닌" 픽셀은 없어야 한다.

**1-3. 색 비교는 밝기를 포함한다.** a\*b\*만 쓰면 흰 하늘과 어두운 회녹색 잎이 같은 색이 된다(`p78`: 하늘색 허용치 20에서 나무의 38–48 %).

**1-4. 의미를 바꾸기 전에 사용자 말로 규칙을 한 줄씩 적고 확인한다.** "Replace", "Keep" 같은 이름은 사람마다 다르게 읽는다.
동작 표(위 1-1처럼)를 먼저 맞추고 구현한다.

## 2. 현재 동작

### 2-1. Range 처리 순서

```
① 색 고르기 → ② 필터로 A 만들기 → ③ (Invert면 A↔나머지) → ④ 판정 영역으로 자르기 → ⑤ 동작(넣기/빼기) → ⑥ 미리보기 → ⑦ 적용
```

**BC-1. 색 고르기.** Range를 고르면 **고른 색이 아직 없을 때만** Pick Color가 저절로 켜진다(이미 있으면 꺼진 채, 눈치 못 챈 클릭이 고른 색을 바꾸지 않게, `p92`). 고른 색 바꾸기(클릭, Shift+클릭, 썸네일, Clear)는 `Ctrl+Z` / `Ctrl+Y`로 되돌린다(`p92`). 클릭 = 그 자리 **1 px 색**(작업 해상도 픽셀, `p93`; 전에는 5×5 평균) 하나로 **교체**, **Alt**+클릭 = 5×5 평균색(`p95`, Shift와 같이 쓰면 평균색 추가),
Shift+클릭 = 하나 **추가**(최대 8개, 넘으면 오래된 것부터 버림). `Clear` = 전부 지움. 색은 화면 이미지(작업 해상도, BC-16)에서 읽는다.
고른 색 썸네일을 누르면 그 색만 지운다(`p90`).
- 피드백:

**BC-2. 색 필터 (Color within, 기본 켜짐, 허용치 30).** 고른 색 **중 하나라도**와 Lab 거리(밝기 L 0–100, a\*, b\*)가 허용치 이하면 A.
밝기 차이도 거리에 들어간다(`p78`). 예: 같은 하늘색이라도 밝기가 30 넘게 다르면 A가 아니다.
- 피드백:

**BC-3. 밝기 필터 (Brightness from … to, 기본 꺼짐).** 회색값(0–255)이 범위 안이면 A.
색 필터와 **둘 다 켜면 AND**(둘 다 만족해야 A). 색을 안 골랐고 밝기도 꺼져 있으면 A가 비고 영역 전체가 B가 된다(아래 BC-6 ※).
- 피드백:

**BC-4. Invert.** A와 B를 바꾼다(필터가 잡은 픽셀 = B, 나머지 = A). 판정 영역이나 동작 종류는 그대로.
- 피드백:

**BC-5. 판정 영역 (Near edge, 기본 켜짐 30 px).** **지금 마스크의 경계**에서 안쪽·바깥쪽으로 30 px 이내만 판정한다(화면의 옅은 흰 띠).
띠 밖은 A든 B든 **그대로**. 끄면 이미지 전체. Region 박스가 있으면 그 안으로 한 번 더 자른다. 이미지 테두리는 경계로 치지 않는다.
- 피드백:

**BC-6. 동작 (Changes).** 판정 영역 안에서만:

| Changes | A (잡힌 픽셀) | B (영역 안 나머지) |
|---|---|---|
| Add A & Remove B (기본) | 마스크에 넣음 | 마스크에서 뺌 |
| Add only (A) | 넣음 | 그대로 |
| Remove only (B) | 그대로 | 뺌 |

※ 색을 하나도 안 고른 채 기본 동작(또는 Remove only)이면 영역 안 전부가 B라서 **띠 안의 마스크가 전부 빠진다**(규칙대로지만, Range를 막 고른 순간 미리보기가 띠 전체 주황으로 보임). 색을 고르기 전에는 아무 것도 안 바꾸게 할지 확인 필요.
- 피드백:

**BC-7. 미리보기.** (`p86`) 판정 영역의 **모든 픽셀을 A = 파랑, B = 주황**으로 칠한다. 실제로 바뀌는 픽셀(A인데 마스크 밖 = 넣음, B인데 마스크 안 = 뺌)은 진하게, 그대로인 픽셀은 옅게. 원래 마스크 색은 그 아래로 비쳐 보이고(색을 덮어쓰지 않고 섞음) 경계는 흰 선. 전에는 바뀌는 픽셀만 칠해서, A인데 이미 마스크 안이거나 B인데 이미 밖인 픽셀이 "둘 다 아닌" 것처럼 보였다. 패널에 `Will apply: +N px / −N px`. 진하기는 툴바 `Overlay` 슬라이더(`p88`).
설정을 바꾸면 잠깐 뒤 다시 계산한다(작업 해상도 기준, 화면 스레드 밖). 계산 중에는 A / B 색을 그리지 않는다.
- 피드백:

**BC-8. 적용.** 오토 툴 공통 규칙([`auto-tools-rules.md`](auto-tools-rules.md) 4장): Fill 모드는 Enter로 전체 결과 적용(Undo 한 번), Paint 모드는 붓으로 문지른 곳만.
`Apply to All Frames`: 같은 설정·같은 고른 색으로 이 Object의 다른 프레임에도 적용(프레임마다 그 프레임 마스크의 경계로 띠를 다시 잡음).
- 피드백:

### 2-2. Auto: Color / Auto: Brightness (색을 고르지 않는 방식)

**BC-10. Auto: Color.** 띠 안의 색을 8개 무리로 나누고(k-means, Lab), 지금 마스크가 **절반 넘게** 덮은 무리는 마스크 쪽, 아니면 밖으로 다시 칠한다.
Balance가 50보다 크면 마스크 쪽을 더 많이 준다. 마스크가 대충 맞아야 결과가 맞다. (미리보기는 A / B가 아니라 넣음 / 뺌만.)
- 피드백:

**BC-11. Auto: Brightness.** 띠 안 회색값에 Otsu 기준선 하나. 마스크 쪽이 더 밝으면 밝은 픽셀이 마스크.
- 피드백:

### 2-3. 기대와 어긋날 수 있는 지점 (확인 필요)

"하늘 마스크 안에 칠해진 나뭇잎 픽셀을 빼기"(`p78` 요청)를 기준으로, 지금 구조에서 안 되는 경우입니다.

**BC-12. 마스크 안쪽 깊숙이 있는 잎은 판정 영역 밖.** 띠는 **마스크 경계** 기준이다. 하늘 마스크가 잎을 덮어 버렸다면 그 자리에는 경계가 없어서,
경계에서 30 px보다 먼 잎은 아무리 색을 골라도 안 바뀐다. 해결 후보: (a) 그 작업에는 Near edge 끄기(+ Remove only), (b) 띠 기준을 "마스크 경계"가 아니라 "마스크 안 전체"로 바꾸는 옵션.
- 피드백:

**BC-13. Near edge를 끄고 기본 동작(Add & Remove)을 쓰면** 이미지 전체에서 고른 하늘색과 비슷한 것(흰 벽, 흰 차, 밝은 도로)이 마스크에 **들어온다**. 잎만 빼려면 Remove only가 맞다. 기본 동작을 바꿀지, 경고를 띄울지.
- 피드백:

**BC-14. 고른 색은 1 px** (`p93`에서 5×5 평균 → 1 px). 잎 가장자리나 구름 경계를 클릭해도 섞인 평균이 아니라 그 픽셀 색. 대신 노이즈가 많은 곳은 한 픽셀이 튈 수 있다(그때는 Alt+클릭으로 5×5 평균, 또는 Shift+클릭으로 여러 개). 1 px도 작업 해상도(BC-16) 픽셀이다.
- 피드백:

**BC-15. 하늘 그라데이션.** 지평선 쪽 흰 하늘과 위쪽 파란 하늘은 Lab 거리가 30을 쉽게 넘는다. 지금은 Shift+클릭으로 여러 색(최대 8개)을 골라야 한다. 기본 허용치나 최대 개수를 바꿀지.
- 피드백:

**BC-16. 작업 해상도 1024 px(긴 변).** 계산과 미리보기가 줄인 이미지에서 이뤄지고 저장 때 원본 크기로 늘린다. 원본에서 1–3 px인 잎 사이 하늘 틈은 줄인 이미지에서 이미 잎색과 섞여 **어느 필터에도 안 잡힐 수 있다**. 원본 해상도로 계산하는 옵션이 필요한지.
- 피드백:

**BC-17. 경계의 섞인 픽셀.** 잎 가장자리 픽셀은 하늘색도 잎색도 아니어서 허용치에 따라 들어갔다 빠졌다 하며 점 노이즈가 남는다. 지금은 Remove Specks / Fill Holes를 따로 돌려야 한다. By Color 안에 정리 단계를 넣을지.
- 피드백:

**BC-18. 적용하면 띠가 움직인다.** 적용 후 마스크 경계가 바뀌므로 다음 계산의 띠도 바뀐다. 같은 설정으로 두 번 적용하면(Apply & Continue) 결과가 더 번질 수 있다.
- 피드백:

**BC-19. 그 외 "안 되는" 장면.** 어떤 이미지(크롭 번호), 어떤 설정(By / Changes / Near edge / 고른 색 / 허용치 / Invert)에서 무엇을 기대했고 무엇이 나왔는지 적어 주시면 실제 앱 경로로 재현해 숫자·캡처로 확인하겠습니다(공통 수칙 6장).

### BC-P3 상세: 원본 보기

- **지금**: 고르는 값은 이미 원본 픽셀이다(`Canvas.sample_color`는 `self.image`를 읽음, 오버레이와 무관). 문제는 **보이는 것**뿐이다. `H`(Hide Masks)는 Object 색만 숨기고 오토 툴 표시(A 파랑 / B 주황, 회색, Near edge 흰색), 에딧 레이어 초록 / 빨강, 범례는 그대로 남는다. `Z` / `V`는 흑백 미리보기라 원본이 아니다.
- **a. 보이는 것**: 원본 보기 중에는 사진만 그린다. 모든 Object 색, 에딧 레이어, 오토 툴 표시, Region, 후보, 범례를 숨긴다. 남기는 것: 커서(픽커 십자), 배너. 배너 앞에 `ORIGINAL ·`을 붙여 숨긴 상태임을 항상 보이게 한다(수칙 3장: 숨긴 상태를 눈치 못 채는 일 방지).
- **b. 키 `T`** (지금 빈 키): 짧게 누르면 켜기 / 끄기, 0.3초 넘게 누르고 있으면 떼는 순간 원래대로(잠깐 보기). `V`(토글) / `Z`(누르고 있기)를 키 하나로.
- **c. 버튼**: 픽커 옆에 `Original (T)` 체크 버튼. 마우스로만 써도 되게.
- **d. 꺼지는 때**: 픽커를 끄거나 오토 툴을 나가면 원본 보기도 끈다. 결과(A / B)를 보며 판단해야 하는 화면에 숨긴 채 돌아오지 않게. 켜는 것은 자동으로 하지 않는다(p92 교훈: 모르는 새 바뀐 상태가 작업을 날림).
- **e. 고르는 동작은 그대로**: 원본 보기 중에도 클릭 / Shift / Alt 픽이 같고, 고르면 스와치와 결과 계산도 바로 바뀐다(보일 때 반영).
- **f. (선택) 고른 자리 표시**: 원본 보기 중 고른 색의 위치에 작은 `+`와 스와치 번호. 어디서 찍었는지 다시 확인하고 스와치를 눌러 지울 때 짝을 찾기 쉬움.
- 추천: a + b + d 먼저, c는 함께(작음), f는 써 보고.

### BC-P4 상세: 조건별 뒤집기와 빼는 색

**문제 (사용자 화면, 2026-10-07)**: 단풍 든 나무 위 하늘. `Brightness from`으로 밝은 잎을 잡으면 잘 잡히지만 밝은 하늘·구름 일부도 A가 된다.
밝기만으로는 "밝은 잎"과 "밝은 하늘"을 가를 수 없고, 색(노랑·초록 대 파랑·흰색)이 가른다.

**지금 규칙**: `A = (고른 색 근처) ∧ (밝기 범위 안)`, Invert = A 전체를 B와 바꿈. 색 조건은 "이 색만 남긴다"(좁히기)로만 쓸 수 있고,
"이 색은 뺀다"는 표현할 방법이 없다.

**제안 규칙** (조건은 모두 ∧, 각 조건에 `Not`):

| 조건 | 켬 | `Not` 체크 |
|---|---|---|
| 밝기 `lo–hi` | 범위 안 | 범위 밖 |
| 고른 색(+) | 어느 + 색과 허용치 안 | 모든 + 색에서 허용치 밖 |
| 빼는 색(−) (b) | 어느 − 색과 허용치 안이면 **A에서 뺌** | (없음: 이미 빼기) |

- 예: 위 화면 = `밝기 140–255` ∧ `Not 색(하늘 파랑, 구름 흰색)`. 또는 `밝기` ∧ `−색(하늘, 구름)`.
- **a. 조건별 `Not`** (사용자 제안 그대로): `Color within` 줄과 `Brightness from` 줄에 각각 `Not` 체크. 지금의 전체 Invert는 `Swap A / B`로 이름을 바꿔 남김(1-1 규칙 그대로: A와 B만 바꿈).
- **b. 빼는 색(− 스와치)**: + 색과 − 색을 한 번에 쓰게. 색 고르기 중 **우클릭 = 빼는 색 추가**(Alt = 5×5 평균은 같이 적용), 좌클릭은 지금처럼 + 색. 스와치 줄을 `+ ■■  − ■■`로 나누고 클릭 = 그 색 지우기(p90 그대로). 허용치는 + / − 따로(`Color within` / `Except within`), 처음엔 같은 값.
  - a만으로도 위 예는 되지만 + 색으로 좁히면서 − 색으로 빼기(예: 노란 잎만, 그중 하늘에 비친 흰 테두리는 빼기)는 b가 있어야 함. Photoshop Color Range의 + / − 스포이트와 같은 감각.
- **c. 밝기 범위를 클릭으로**: 색 고르기 중 `Ctrl+Shift+클릭`(또는 Brightness 줄의 스포이트 버튼)으로 찍은 픽셀들의 밝기로 `lo–hi`를 넓힘. 지금은 숫자로만 맞춤.
- **d. 보이기**: 범례에 조건 요약 한 줄(예: `A = 밝기 140–255 · 하늘색 아님`). 스와치 툴팁에 + / − 표시. Original(T, p96)로 원본과 번갈아 보며 맞춤.
- **e. 저장값**: 설정 키 `color_not`, `bright_not`, `color_samples_out`, `color_tol_out`. 옛 `color_invert`는 `swap`으로 읽음. 고른 색 Undo(p92)는 − 색도 같이.
- 추천 순서: **a → b → d**, c는 써 보고. a는 작은 변경(조건마다 `~` 하나)이고 위 문제를 바로 풂. b는 UI(스와치 두 줄, 우클릭)가 조금 큼.

### BC-P5 상세: Auto 방식 정리

- **지금**: `By`에 `Auto: Color`(띠 안 색 8 무리, 마스크가 절반 넘게 덮은 무리 = 마스크), `Auto: Brightness`(띠 안 Otsu 기준선 하나), `Range`. 기본값 Auto: Color.
- **문제**: 마스크 경계가 대충 맞아야 결과가 맞고(틀린 쪽을 배움), 무엇을 기준으로 갈랐는지 안 보이며, 손잡이가 Balance 하나뿐. A / B 미리보기도 없음(넣음 / 뺌만).
- **a. 기본값 Range, Auto 두 개는 목록에서 뺌.** 설정에 Auto가 저장돼 있으면 Range로 열고 로그로 알림. 코드(`split_by_color`)는 테스트와 함께 지움(CLI 배치에서도 안 씀).
- **b. 다시 만든다면 "색 제안" 버튼으로**: `Suggest colors`를 누르면 지금 마스크의 경계 띠에서 안쪽 대표색은 + 스와치, 바깥 대표색은 − 스와치로 채움(k-means, BC-P4 b가 먼저 필요). 결과는 보통 Range라 A / B가 보이고, 틀린 스와치는 클릭으로 지우면 됨. Auto의 "알아서"는 남기고 "안 보임"은 없앰.
- **c. 밝기 쪽**: 같은 버튼이 안쪽 / 바깥 밝기 분포에서 Otsu로 `lo–hi`를 제안(지금 Auto: Brightness의 기준선을 숫자로 보여 주고 고칠 수 있게).
- 추천: a 먼저(지움, 작음). b / c는 BC-P4 b 다음에.
