# UX 원칙

기능을 넣거나 바꿀 때 지키는 기준입니다. 사용자 피드백([`ideas.md`](../backlog/ideas.md), [`ui-issues.md`](../backlog/ui-issues.md))에서 나온 판단을
일반 규칙으로 적었습니다. 메뉴·툴바 배치는 [`menu-design.md`](menu-design.md), 키는 [`keymap.md`](keymap.md).

## 1. 되돌릴 수 있으면 묻지 않는다
- Undo가 되는 동작은 확인 창 없이 바로 실행합니다. 확인 창은 되돌릴 수 없는 것(예: 전파 중 종료)에만.
- 실수로 지우는 게 걱정되는 것은 확인 창 대신 **잠금**으로 막습니다(Object 잠금).
- 출처: Object 삭제 확인 창 제거 (`v0.4-p17`).

## 2. 들어가면 바로 쓸 것이 켜져 있다
- 모드에 들어가면 그 모드에서 가장 자주 쓰는 도구가 켜진 상태로 시작합니다. 나가는 길(같은 키 한 번 더, `Esc`)이
  가까우면 기본값을 적극적으로 정해도 불편하지 않습니다.
- 예: `E` 편집 = 브러쉬 켜진 채 시작(`D` / `E`로 끔), 오토 툴 = Fill 모드로 시작, Paint 모드 = 전체 선택으로 시작.
- 출처: `v0.4-p10`, `v0.4-p15`.

## 3. 같은 결과로 가는 길은 같은 상태에서 시작한다
- 버튼과 단축키가 같은 곳으로 가면 결과 상태도 같아야 합니다. 예: Paint 버튼 = `A`(둘 다 전체 선택된 Paint 모드).
- 출처: `v0.4-p15`.

## 4. 말로 설명되는 기본 동작은 선택지로 묻지 않는다
- "먼저 고른 것을 나중에 고른 것에 더한다"처럼 한 문장으로 설명되는 동작은 창을 띄우지 않고 바로 실행합니다.
- 세부 설정이 필요하면 버튼 옆의 작은 옵션 버튼(`⚙`)으로 따로 둡니다. 기본 버튼은 한 번에 끝납니다.
- 출처: Copy / Merge 단순화 (`v0.4-p17`).

## 5. 키 하나에 뜻 하나, 상황은 마우스 위치로 나눈다
- 같은 키가 두 가지 일을 하거나 다른 키와 역할이 겹치면 뺍니다(`S` 스크롤 제거).
- 목록에서만 필요한 키는 **마우스가 그 목록 위에 있을 때만** 다른 뜻을 갖습니다(`W A S D`, `Space`). 캔버스의 키는 그대로.
- 출처: `v0.4-p13`, `v0.4-p15`.

## 6. 누르고 있어도 토글은 한 번
- 켜기/끄기 키는 자동 반복하지 않습니다. 누르고 있는 동안만 보이는 것은 `Z`처럼 따로 둡니다. 이동 키는 반복합니다.
- 출처: `X` 깜빡임 (`v0.4-p15`).

## 7. 실수 한 번이 비싼 키는 두지 않는다
- 자주 누르는 키 옆에 앱 종료처럼 되돌리기 어려운 키를 두지 않습니다. 메뉴에만 둡니다.
- 출처: `Ctrl+Q` 제거.

## 8. 상태는 아이콘보다 칸 색으로
- 목록의 상태는 작은 아이콘보다 칸의 색이 빨리 읽힙니다. 지금 보고 있는 것 = 진한 칠, 기준처럼 따로 기억할 것 =
  **다른 색**의 테두리(같은 색끼리는 구분이 안 됨), 여러 개 고른 것 = 옅은 칠.
- 켜져 있을 때만 의미가 있는 표시(🔒)는 꺼져 있을 때 비워 둡니다. 필요할 때 마우스를 올리면 흐리게 보입니다.
- 출처: `v0.4-p16` → `v0.4-p19` (열린 프레임 칠, 기준 ◎ 주황 테두리), 잠금 칸.

## 9. 메뉴는 기능 목록이자 키 교과서
- 모든 명령은 메뉴에 있고 키가 옆에 보입니다. 툴바에는 작업 중 계속 켜고 끄는 것만. 자세히는 [`menu-design.md`](menu-design.md).
